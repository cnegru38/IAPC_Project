in git bash - from root (you only need to do this part the first time):

ollama pull llama3.2
ollama pull nomic-embed-text

-- only if you have access to .env --
copy and paste .env in two places:
1) in root, next to docker-compose.yml, .gitignore, etc
2) in ingest-static/src/main/resources, next to application.yaml

do not rename the file!

it's gitignored as per project rule "No secrets in the repository, and configuration is documented."

to test if ollama is running:
- run EdupulseApplication in intellij (or ./mvnw spring-boot:run from ingest-static) <- note: needs docker engine running

- then, in git bash - from root:
curl -X POST http://localhost:8081/api/ollama/chat/summarize \
  -H "Content-Type: text/plain" \
  -d "Spring AI is a framework that provides abstractions for working with AI models. It supports chat, embeddings, and vector stores across many providers."

or from one command line:
curl -X POST http://localhost:8081/api/ollama/chat/summarize -H "Content-Type: text/plain" -d "Spring AI is a framework that provides abstractions for working with AI models. It supports chat, embeddings, and vector stores across many providers."

WARNING: ollama can be slow when ran locally. it should work but it takes time.

to test if database exists (in git bash - from root):
docker exec -it pgvector psql -U edupulse -d edupulse -c "\dt"

-- HOW TO RUN AFTER REFACTORING PROJECT STRUCTURE --
0. in case you have the old pgvector database - it needs to be deleted and recreated
in git bash - from root, run these in order, with docker desktop running :

docker compose -p resources down -v
docker compose up -d --build

wait about 2-3 minutes for everything to be recreated, then run
docker compose ps

and everything should say "Healthy"

1. check these to make sure everything works as intended:
a. eureka server is connected to the api gateway
http://localhost:8761/ - should list "API_GATEWAY" as an instance currently registered with eureka
if it doesn't just keep refreshing until it appears, it takes a few minutes

b. api gateway works
in git bash from root - run:
curl http://localhost:8080/actuator/health
you should get {"groups":["liveness","readiness"],"status":"UP"}

c. test if database exists (same as above)
docker exec -it pgvector psql -U edupulse -d edupulse -c "\dt"

note: running from intellij (VERY optional)

apps that use the database (edupulse, the story services) need the pgvector container running, so docker must be up.
HOWEVER - each service runs either in docker or in intellij, never both.
this means if the docker containers for eureka-server or api-gateway are up, they will fail to build from intellij.
before starting one from intellij, you have to stop their containers manually.
in git bash:
docker compose stop eureka-server
docker compose stop api-gateway

then you can run the apps from intellij

to turn the containers back on:
docker compose up -d
